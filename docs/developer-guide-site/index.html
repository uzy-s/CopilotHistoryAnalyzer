Project Overview

This Streamlit app analyzes GitHub Copilot chat export JSON files, recreates chat sessions, and compares AI activity with optional local Git commit history.

  • Reconstructs transcript-style chat sessions.
  • Calculates token, latency, and prompt-style metrics.
  • Builds timeline and phase-to-phase comparisons.
  • Supports optional Git correlation for human contribution context.

Quick Start

python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:APP_PASSWORD = "your-password"
streamlit run app.py

Alternative auth config: use .streamlit/secrets.toml with APP_PASSWORD = "your-password".

To load JSON-driven API docs in browser reliably, serve this folder: python -m http.server 8080 and open http://localhost:8080.

Applied Development Patterns

Layered Architecture

UI orchestration lives in app.py, reusable business logic in services/, and presentation rendering in views/tabs.py.

Functional Core, UI Shell

Analytics helpers are mostly pure functions returning deterministic values, while Streamlit-specific effects are contained in render/auth orchestration.

Defensive Parsing Boundary

parse_chat_data and related helpers isolate malformed input handling, enforce defaults, and keep downstream views stable.

Progressive Enhancement

Optional git correlation augments metrics when available without blocking base chat analysis workflows. If missing phases exist in the universal data but not the local Git data, the views gracefully fall back.

Runtime Pipeline

  1. Authenticate early with require_password() (fail-fast gate).
  2. Collect sources from phase discovery + universal files auto-discovery.
  3. Instantly pre-process universal JSON items to discover "hidden" phases (e.g. Phase 3).
  4. Normalize chat exports into request-level rows.
  5. Optionally parse git history (assigning it to user-selected "Phase" mapped dynamically).
  6. Apply session filters and render via modularized tab components in views/.

Universal Data Flow

The analyzer acts natively on a specialized data set known as "Universal Synthesis JSON." This data schema represents multi-modal, merged inputs spanning raw Copilot chat logs, manual tracking workbooks, Git repository timelines, and external grading metrics (like RITM files).

Auto-Discovery Mechanism

Synthesized files located in synthesis/universal/*/*_universal.json are automatically detected by discover_universal_files(). The UI no longer requires developers to manually multiselect these files. They form the unified baseline right out of the box.

Dynamic Phase Mapping

When a tracking workbook introduces a phase entirely missing from the raw /data directory (e.g., "Phase 3"), the universal phase collector automatically registers it. Any supplemental Git repositories attached via the sidebar can dynamically map to these "hidden" phases natively.

Metrics Roll-up

To decouple heavy logic from UI redraws, all KPIs are aggregated by helper functions like _aggregate_universal_phase_metrics into a Phase-level dataframe before rendering, heavily utilizing pandas defensive NaN/empty handling to guarantee crash-free charting.

Data Contract

Input: chat JSON with top-level requests array.

Key Parsed Request Fields

  • timestamp
  • message.text
  • response[]
  • result.details, result.usage.*, result.timings.*
  • variableData.variables[].value.path|fsPath
  • editedFileEvents

Primary Output DataFrames

  • df_chat: timestamp, model, tokens, code lines, phase, context metadata
  • df_git: timestamp, author, message, insertions, deletions, files

Developer Workflow

  1. Keep parsing and business logic in services/.
  2. Keep UI rendering in views/ components.
  3. When adding analytics, build pure functions first, then render outputs.
  4. When adding tabs, create renderer + wire in app.py.
  5. Preserve backward compatibility for chat schema changes.

Updating and Deploying

The project operates as a standard Streamlit web application, meaning deployment consists of pushing the codebase to a host and running the execution command.

Local Updates

  1. Pull the latest code from the main repository.
  2. Ensure dependencies are up-to-date: pip install -r requirements.txt
  3. Run the application locally: streamlit run app.py

Production Deployment

When deploying to a production server (or Streamlit Community Cloud / Azure / AWS):

  1. Provision a Python 3.9+ runtime environment.
  2. Install system-level dependencies (if using external graphing libraries that require C-extensions, though strictly native python libraries are used currently).
  3. Execute pip install -r requirements.txt.
  4. Start the server using Streamlit's headless mode to ensure proper binding: streamlit run app.py --server.headless true --server.port 8501

QA Checklist

  • App starts and sign-in prompt appears.
  • Valid password grants access.
  • Phase selection and manual upload both parse correctly.
  • Statistics, timeline, comparison, and prompt tabs render without errors.
  • Git correlation works with valid repo path.

Known Limits and Future Work

  • Success/error metrics are heuristic, not ground-truth correctness.
  • Git insertion counts represent volume, not authorship certainty.
  • Future work: add automated tests, richer schema validation, and export features.
